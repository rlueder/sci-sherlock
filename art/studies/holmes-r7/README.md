# Holmes r7: anatomy-guided animation

**Subsequent review:** independent generated frames vary in head shape, colour
placement and body width. The first walk half is too thin. Keep these as action
studies; use the [fixed character master](../../reference/holmes-master-v1/README.md)
for further drawing. Its linked-body puff also supersedes the overly subtle puff here.
The width-only generation draft is preserved as `generated/walk-width-superseded.png`
and was not promoted, because it did not solve the underlying identity drift.

Open `/art/studies/holmes-r7/` on the local art server. It plays pipe puff, thinking,
cap adjustment, pocket-watch inspection and a six-cel east-facing walk study. Pause,
step, scrub, slow playback, or enable **Overlay joints** to review individual poses.
All are motion studies awaiting review; no game YAML, Yarn or runtime assets changed.

The user approved the r6 costume poses and requested animation with anatomy mapped
first. The r5 grafted-limb method remains rejected. Every new body cel here is a
complete rendered figure. Conversion only registers and samples whole frames.

## Build the structure before drawing the motion

1. `build-guides.ts` maps the approved poses' head, neck, shoulder, elbow, wrist,
   pelvis, hip, knee, ankle and toe landmarks. The overlay is saved in
   `review/approved-pose-skeletons.png`. Cyan denotes the near side, amber the far
   side. Joints beneath coat fabric are artist estimates, not recovered anatomy.
2. The same script constructs an eight-pose walking plan. Projected thigh and shin
   lengths are constant within each side (24 px near, 22.5 px far); the shorter far
   side is a drawing approximation of depth, not an anatomical length difference.
   Knee bends are solved from hip/ankle targets. This is a 2D guide, not a fitted 3D rig.
3. Skeleton-only references did not reliably prevent the image generator repeating
   the same leading leg. Adding coloured limb thickness and making that mannequin
   the primary pose reference produced clearer near/far alternation. Both mannequin
   half-strides and the exact source prompts are preserved.
4. Render the entire character around that structure: shoulders, sleeves, chest,
   pelvis, legs and hanging overcoat skirts together. The guide never deforms or
   paints onto the original sprite. Guide colours are excluded from game exports.
5. Register complete frames, convert to the approved palette, then inspect motion at
   native resolution. `rendered-joints.json` contains separate, editable per-key-frame
   annotations for the preview. These are visual diagnostics, not animation drivers.

## Files and reproduction

```sh
pnpm exec tsx art/studies/holmes-r7/build-guides.ts
pnpm exec tsx art/studies/holmes-r7/build-animation.ts
pnpm art check art/studies/holmes-r7/art.json
pnpm typecheck
PIXELORAMA_BIN=/path/to/Pixelorama pnpm exec tsx art/studies/holmes-r7/verify-native.ts
```

- `generated/`: source PNGs and exact prompts from the built-in ImageGen tool.
  `walk-draft`, `walk-opposite-draft` and `watch-rejected` are failed experiments,
  retained for teaching. The first watch draft switched the acting arm; it is not used.
- `source/`: four whole-body key drawings per idle, selected walk keys, and five
  editable Pixelorama 1.2.3 timeline masters. Holds are explicit repeated cels at 8 fps.
- `export/`: 72×120 indexed-colour PNG cels with binary alpha. Anchor [36,113].
- `animation.json`: frame order, timing and source registration measurements.
- `anatomy.json`: initial pose/stride construction, generated by `build-guides.ts`.
- `rendered-joints.json`: reviewed projected annotations for the converted drawings;
  edit this file when refining an overlay. Do not mistake an overlay for an accuracy test.
- `review/`: GIF loops, in-room GIFs, contact sheets and construction images.
- `art.json`: isolated view 206 idle study and view 200 east walk study. It references
  the approved r6 neutral cel; it is not a complete four-direction runtime delivery.
- `native-export-check.json`: actual Pixelorama export verification, independent of
  the TypeScript writer. Five masters, 97 timeline cels, identical decoded pixels.

The converter uses alpha threshold 200 and nearest sampling into the existing
64-colour palette. Each sheet has one uniform scale, based on a 106-pixel first-figure
height. No per-frame body stretching or limb compositing occurs. Idle whole-frame
translation registers the near sole; walking uses torso registration so a moving
foot is not artificially pinned. Display copies apply 1:1.2 pixel aspect. PNG alpha
and palette checks are distinct from visual review.

The eight-pose planning guide yielded redundant contact drawings. Six selected cels
form the walk study: near contact/support, far swing, far contact/support, near swing.
The unused fourth drawing on each successful source sheet remains available.

## Review limits and next production work

The idle actions are short key-frame sequences with held poses and a reverse return;
they are not optical-flow interpolation. The watch loop begins with the watch already
held low. Pocket retrieval, replacement and transition to the shared standing cel
still need full-body drawings before runtime use. The arm-switching draft was rejected.

The walk is an in-place review loop. Contact, stride distance, near/far shoe angle and
body consistency between the two generated sheets still need refinement; no claim of
zero foot sliding is made. Do not integrate it merely because the file checks pass.
Generated frames can also shimmer in small cloth/face clusters; use native Pixelorama
onion skins to clean temporal consistency while retaining coherent anatomy.

ImageGen is proprietary. The saved sources and prompts make that dependency explicit.
The joint guide, conversion, editable Pixelorama masters and export are an open-source
workflow and can instead accept hand-drawn whole figures. No new application was
installed for this pass; native verification used the previously obtained Pixelorama
1.2.3 executable. Blender remains available for stronger 3D construction work, but
this pass's new skeleton is the documented 2D guide, not a newly fitted Blender rig.
